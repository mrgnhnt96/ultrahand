# Sources

The citation keys used in [checklist.md](checklist.md) and [SKILL.md](../SKILL.md). Keys
with a `mobile:`, `tablet:` or `desktop:` prefix are in that skill's own
`references/sources.md`.
The composition keys (`SEC-n`, `SCR-n`, `NNG-VH`, `NNG-PROX`, `NNG-REGION`, `NNG-SIM`,
`NNG-CLICK`, `NNG-GRID`, `NNG-MINIMAL`, `NNG-PD`) and their sources are in
[shared/composition/principles.md](../../../shared/composition/principles.md).
Sources were checked in November 2026.

## Review method

| Key | Source |
| --- | --- |
| NNG-HEURISTICS | Jakob Nielsen, *10 Usability Heuristics for User Interface Design*, Nielsen Norman Group, 1994, last reviewed January 2024. The heuristics are keyed NNG-H1 to NNG-H10 in the checklist. https://www.nngroup.com/articles/ten-usability-heuristics/ |
| NNG-SEVERITY | Jakob Nielsen, *Severity Ratings for Usability Problems*, Nielsen Norman Group, 1994 (frequency, impact, persistence; 0 to 4 scale, 4 = usability catastrophe, imperative to fix before release). https://www.nngroup.com/articles/how-to-rate-the-severity-of-usability-problems/ |
| NNG-HE | Kate Moran and Kelley Gordon, *How to Conduct a Heuristic Evaluation*, Nielsen Norman Group, 2023 (several evaluators, because one misses problems; two passes through the interface). https://www.nngroup.com/articles/how-to-conduct-a-heuristic-evaluation/ |
| NNG-CW | Kim Flaherty, *Evaluate Interface Learnability with Cognitive Walkthroughs*, Nielsen Norman Group, 2022 (the four questions asked at each step). https://www.nngroup.com/articles/cognitive-walkthroughs/ |
| WHARTON-94 | Cathleen Wharton, John Rieman, Clayton Lewis and Peter Polson, "The cognitive walkthrough method: A practitioner's guide", in Jakob Nielsen and Robert Mack (eds.), *Usability Inspection Methods*, Wiley, 1994. |
| NNG-FITTS | Raluca Budiu, *Fitts's Law and Its Applications in UX*, Nielsen Norman Group, 2022 (larger and closer targets are faster; labels widen targets; screen edges help pointers but not touch; context menus next to their item). https://www.nngroup.com/articles/fitts-law/ |

## Desktop platforms

| Key | Source |
| --- | --- |
| HIG-MACOS | Apple, *HIG: Designing for macOS* (large displays: more content, fewer nested levels, less modality; resizable windows and full screen; every command in the menu bar; keyboard shortcuts; precise pointer). https://developer.apple.com/design/human-interface-guidelines/designing-for-macos |

## Controls, scrolling and panning

| Key | Source |
| --- | --- |
| HIG-SEGMENTED | Apple, *HIG: Segmented controls* ("Limit the number of segments in a control. Too many segments can be hard to parse and time-consuming to navigate. Aim for no more than about five to seven segments in a wide interface and no more than about five segments on iPhone"). https://developer.apple.com/design/human-interface-guidelines/segmented-controls |
| AND-SEGMENTED | Android Developers, *Segmented button* (Compose, Material 3): a multi-select segmented button holds two to five items; for more, use chips. https://developer.android.com/develop/ui/compose/components/segmented-button |
| NNG-LISTBOX | Anna Kaley, *Listboxes vs. Dropdown Lists*, Nielsen Norman Group, 2020 (radio buttons for small sets of about five or fewer; with many options a listbox, or a dropdown where space is limited). https://www.nngroup.com/articles/listbox-dropdown/ |
| NNG-DROPDOWN | Angie Li, *Dropdowns: Design Guidelines*, Nielsen Norman Group, 2017 (a dropdown hides its options; very long ones that scroll can't be scanned at a glance; don't use one where typing is faster). https://www.nngroup.com/articles/drop-down-menus/ |
| HIG-SCROLL | Apple, *HIG: Scroll views* ("Avoid putting a scroll view inside another scroll view with the same orientation"; support the default scrolling gestures and keyboard shortcuts, which people expect to work everywhere; set maximum and minimum zoom scales). https://developer.apple.com/design/human-interface-guidelines/scroll-views |
| APG-SLIDER | W3C WAI, *ARIA Authoring Practices Guide: Slider Pattern* (role `slider`; Right/Up and Left/Down change the value by one step, Home and End go to the first and last allowed value, Page Up and Page Down optionally by a larger step; `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-valuetext` when the number alone isn't clear, `aria-orientation="vertical"` for a vertical slider; a label from `aria-labelledby` or `aria-label`). https://www.w3.org/WAI/ARIA/apg/patterns/slider/ |
| APG-SPLITTER | W3C WAI, *ARIA Authoring Practices Guide: Window Splitter Pattern* (a focusable `separator` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax`, usually 0 to 100, and `aria-controls` naming the primary pane; arrow keys move a variable splitter; Enter collapses the primary pane and restores it; optionally Home and End for its smallest and largest size, and F6 to cycle panes). https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/ |
| MDN-OVERSCROLL | MDN, *overscroll-behavior* (scroll chaining: at a scroller's boundary the scroll passes to the one beneath; `contain` stops it, for dialogs and overlays whose background shouldn't move). Specified in W3C, *CSS Overscroll Behavior Module Level 1*. https://developer.mozilla.org/en-US/docs/Web/CSS/overscroll-behavior |
